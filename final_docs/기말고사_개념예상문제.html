범위: 6장 조건 처리, 7장 정수 산술, 8장 고급 프로시저, 9장 메모리 관리

6장 조건 처리 Conditional Processing

조건 점프는 signed/unsigned 구분과 flag 조건을 정확히 외우는 쪽이 가장 중요하다.

  1. AND, OR, XOR 명령이 실행되면 CF와 OF는 어떻게 되는가?
    둘 다 0으로 클리어된다.
  2. NOT 명령은 플래그에 어떤 영향을 주는가?
    플래그에 영향을 주지 않는다.
  3. TEST와 AND의 공통점과 차이점을 설명하시오.
    둘 다 bitwise AND 결과 기준으로 flag를 설정한다. AND는 결과를 저장하고, TEST는 결과를 버린다.
  4. CMP와 SUB의 공통점과 차이점을 설명하시오.
    둘 다 뺄셈 기준으로 flag를 설정한다. SUB는 결과를 저장하고, CMP는 피연산자를 바꾸지 않는다.
  5. CMP eax, ebx 후 JA와 JG는 각각 어떤 비교에서 사용하는가?
    JA는 unsigned greater, JG는 signed greater.
  6. signed 비교에서 JA/JB/JAE/JBE를 쓰면 왜 위험한가?
    signed 대소 관계는 SF, OF, ZF 조합으로 판단해야 하므로 음수에서 틀린다.
  7. unsigned 비교에서 JG/JL/JGE/JLE를 쓰면 왜 위험한가?
    unsigned 대소 관계는 CF, ZF 중심으로 판단해야 하므로 최상위 bit가 1인 값에서 틀린다.
  8. JE와 JZ는 어떤 관계인가?
    같은 조건이다. 둘 다 ZF=1.
  9. JNE와 JNZ는 어떤 관계인가?
    같은 조건이다. 둘 다 ZF=0.
  10. JA가 점프하는 flag 조건을 쓰시오.
    CF=0 AND ZF=0.
  11. JBE가 점프하는 flag 조건을 쓰시오.
    CF=1 OR ZF=1.
  12. JG가 점프하는 flag 조건을 쓰시오.
    ZF=0 AND SF=OF.
  13. JL이 점프하는 flag 조건을 쓰시오.
    SF != OF.
  14. 복합 조건 AND를 어셈블리로 구현할 때 보통 어떤 방식으로 분기하는가?
    하나라도 거짓이면 false label로 빠지는 방식이 흔하다.
  15. 복합 조건 OR를 어셈블리로 구현할 때 보통 어떤 방식으로 분기하는가?
    하나라도 참이면 true label로 바로 점프하는 방식이 흔하다.
  16. LOOP 명령은 어떤 레지스터를 자동으로 감소시키는가?
    ECX.
  17. LOOPE와 LOOPNE는 각각 어떤 조건에서 반복하는가?
    LOOPE: ECX != 0 and ZF=1. LOOPNE: ECX != 0 and ZF=0.
  18. LOOP, LOOPE, LOOPNE는 ZF를 변경하는가?
    변경하지 않는다. 직전 명령이 만든 ZF를 사용한다.
  19. MASM의 .IF, .WHILE 같은 고수준 제어 지시어를 사용할 때 주의할 점은 무엇인가?
    MASM이 생성하는 signed/unsigned 비교를 정확히 의식해야 한다.
  20. 소문자를 대문자로 바꿀 때 ASCII에서 보통 어떤 비트를 조작하는가?
    bit 5를 끈다. 보통 AND 11011111b.

7장 정수 산술 Integer Arithmetic

나눗셈은 피제수 크기, 몫/나머지 위치, EDX/CDQ 처리가 핵심이다.

  1. SHL은 산술적으로 어떤 의미를 가지는가?
    왼쪽으로 n비트 shift하면 보통 2^n 곱셈과 같다.
  2. unsigned 정수를 오른쪽으로 나눌 때 SHR을 쓰는 이유는 무엇인가?
    빈자리를 0으로 채워 unsigned 값을 논리적으로 나누기 때문이다.
  3. signed 정수를 오른쪽으로 나눌 때 SAR을 써야 하는 이유는 무엇인가?
    signed 음수의 부호 bit를 유지해야 하기 때문이다.
  4. ROL과 RCL의 차이점을 설명하시오.
    ROL은 CF를 회전 대상에 포함하지 않고, RCL은 CF까지 포함해 회전한다.
  5. MUL의 8비트, 16비트, 32비트 결과 저장 위치를 쓰시오.
    8비트: AX, 16비트: DX:AX, 32비트: EDX:EAX.
  6. IMUL과 MUL의 핵심 차이는 무엇인가?
    MUL은 unsigned, IMUL은 signed 곱셈이다.
  7. DIV의 8비트, 16비트, 32비트 피제수와 몫/나머지 저장 위치를 쓰시오.
    8비트: 피제수 AX, 몫 AL, 나머지 AH. 16비트: 피제수 DX:AX, 몫 AX, 나머지 DX. 32비트: 피제수 EDX:EAX, 몫 EAX, 나머지 EDX.
  8. DIV 전에 상위 절반 레지스터를 0으로 만드는 이유는 무엇인가?
    DIV은 상위:하위 전체를 피제수로 보기 때문에 상위 절반이 쓰레기 값이면 잘못된 피제수가 된다.
  9. IDIV 전에 CBW, CWD, CDQ를 사용하는 이유는 무엇인가?
    signed 피제수를 올바르게 상위 절반까지 부호 확장하기 위해서다.
  10. CBW, CWD, CDQ가 각각 어떤 크기의 부호 확장을 수행하는지 쓰시오.
    CBW: AL -> AX, CWD: AX -> DX:AX, CDQ: EAX -> EDX:EAX.
  11. IDIV에서 나머지의 부호는 무엇을 따라가는가?
    피제수의 부호를 따른다.
  12. DIV 또는 IDIV에서 divide error가 발생하는 대표적인 경우 2가지를 쓰시오.
    divisor가 0인 경우, 또는 몫이 destination 크기에 들어가지 않는 경우.
  13. ADC가 일반 ADD와 다른 점은 무엇인가?
    CF까지 더한다.
  14. SBB가 일반 SUB와 다른 점은 무엇인가?
    CF까지 뺀다.
  15. 큰 정수 덧셈에서 하위 워드를 먼저 계산해야 하는 이유는 무엇인가?
    하위 계산에서 발생한 carry/borrow를 상위 계산에 전달해야 하기 때문이다.
  16. MUL 실행 후 CF, OF는 언제 1이 되는가?
    결과의 상위 절반이 0이 아니면 CF=1, OF=1.
  17. SHL로 곱셈을 최적화할 때 IMUL보다 항상 좋은가? 주의할 점을 설명하시오.
    항상 좋은 것은 아니다. 표현이 복잡해질 수 있고 overflow, signed 의미, 가독성을 고려해야 한다.
  18. 파일 날짜 필드에서 bit mask와 shift를 같이 쓰는 이유는 무엇인가?
    특정 bit field만 분리하기 위해 mask로 불필요한 bit를 지우고 shift로 위치를 맞춘다.
  19. EDX:EAX 표기에서 EDX와 EAX는 각각 어떤 역할을 하는가?
    EDX는 상위 32비트, EAX는 하위 32비트.
  20. signed 산술식 문제에서 CDQ를 빼먹으면 어떤 문제가 생길 수 있는가?
    EDX:EAX 피제수의 부호 확장이 틀려 IDIV 결과가 틀리거나 divide error가 날 수 있다.

8장 고급 프로시저 Advanced Procedures

스택 프레임은 [ebp+] 매개변수, [ebp-] 지역 변수, ret n 정리 바이트를 묻기 쉽다.

  1. stack frame을 사용하는 이유를 설명하시오.
    매개변수와 지역 변수를 안정적으로 접근하고 호출 전후 stack을 관리하기 위해서다.
  2. 표준 stack frame에서 EBP는 어떤 역할을 하는가?
    현재 프로시저 stack frame의 기준 주소 역할을 한다.
  3. push ebp / mov ebp, esp를 하는 이유는 무엇인가?
    caller의 EBP를 보존하고 현재 ESP를 새 기준점으로 만들기 위해서다.
  4. 일반적으로 [ebp+8]에는 무엇이 위치하는가?
    첫 번째 매개변수.
  5. 일반적으로 [ebp+12]에는 무엇이 위치하는가?
    두 번째 매개변수.
  6. 일반적으로 [ebp-4] 같은 음수 offset은 무엇을 의미하는가?
    지역 변수.
  7. RET n에서 n은 무엇을 의미하는가?
    return 후 제거할 매개변수 byte 수.
  8. C calling convention과 STDCALL의 차이점을 설명하시오.
    C convention은 caller가 stack을 정리하고, STDCALL은 callee가 ret n으로 정리한다.
  9. STDCALL에서 stack을 정리하는 주체는 누구인가?
    callee.
  10. C calling convention에서 stack을 정리하는 주체는 누구인가?
    caller.
  11. INVOKE 지시어가 해 주는 일을 설명하시오.
    인수 push, 호출, 타입 검사 등을 MASM이 도와준다.
  12. PROTO가 필요한 이유를 설명하시오.
    프로시저의 이름, 호출 규약, 매개변수 형식을 미리 알려주기 위해서다.
  13. ADDR과 OFFSET의 차이를 설명하시오.
    OFFSET은 전역/static label 주소를 얻을 때, ADDR은 INVOKE에서 변수 주소 전달에 사용되며 지역 변수에도 적합하다.
  14. 배열을 프로시저에 전달할 때 배열 전체가 복사되는가?
    배열 전체가 아니라 시작 주소가 전달된다.
  15. 프로시저 안에서 보존해야 하는 레지스터를 저장하지 않으면 어떤 문제가 생길 수 있는가?
    caller가 기대하던 레지스터 값이 깨져 이후 코드가 오동작할 수 있다.
  16. ENTER와 LEAVE 명령의 역할을 설명하시오.
    ENTER는 stack frame 생성, LEAVE는 stack frame 해제.
  17. 재귀 프로시저에서 stack frame이 중요한 이유는 무엇인가?
    호출마다 독립적인 매개변수, return address, 지역 변수 공간이 필요하기 때문이다.
  18. 지역 변수와 매개변수의 stack 위치 방향 차이를 설명하시오.
    매개변수는 보통 [ebp+...], 지역 변수는 [ebp-...].
  19. procedure call 직후 stack top에는 보통 무엇이 저장되어 있는가?
    return address.
  20. RET 명령이 실제로 하는 일을 설명하시오.
    return address를 pop하여 EIP로 이동하고, 필요하면 ret n으로 매개변수 공간도 제거한다.

9장 메모리 관리 Memory Management

힙 API는 실패 확인과 해제 후 포인터 사용 금지, 페이징은 10/10/12 비트 분해가 핵심이다.

  1. heap memory를 사용하는 이유를 설명하시오.
    실행 중 필요한 크기의 메모리를 동적으로 할당하기 위해서다.
  2. HeapAlloc이 실패했는지 확인하는 대표적인 방법은 무엇인가?
    반환값이 0인지 확인한다.
  3. HeapFree 후 같은 포인터를 계속 사용하는 것이 왜 위험한가?
    해제된 메모리는 더 이상 유효하지 않아 use-after-free 문제가 생긴다.
  4. HeapCreate와 process default heap의 차이를 설명하시오.
    default heap은 프로세스 기본 힙이고, HeapCreate는 별도의 private heap을 만든다.
  5. HeapDestroy는 언제 사용되는가?
    만든 private heap 전체를 제거할 때 사용한다.
  6. HEAP_ZERO_MEMORY 옵션의 의미를 설명하시오.
    할당된 메모리 블록을 0으로 초기화한다.
  7. memory leak이 무엇인지 설명하시오.
    할당한 메모리를 해제하지 않아 계속 점유되는 문제.
  8. dangling pointer가 무엇인지 설명하시오.
    이미 해제되었거나 유효하지 않은 메모리를 가리키는 포인터.
  9. protected mode에서 logical address와 linear address의 차이를 설명하시오.
    logical address는 selector와 offset 형태이고, linear address는 segmentation 변환 후 paging 전 주소이다.
  10. segment descriptor가 포함하는 대표 정보 3가지를 쓰시오.
    base address, limit, access rights/type.
  11. GDT와 LDT의 역할을 간단히 설명하시오.
    GDT는 전역 descriptor table, LDT는 특정 task/process에 대한 local descriptor table.
  12. paging을 사용하는 이유를 설명하시오.
    가상 메모리 제공, 보호, 물리 메모리의 유연한 매핑을 위해서다.
  13. 32-bit linear address가 paging에서 어떤 3개 필드로 나뉘는지 쓰시오.
    page directory index, page table index, page offset.
  14. 32-bit paging에서 page offset은 몇 비트인가?
    12비트.
  15. page size가 4KB일 때 offset이 12비트인 이유를 설명하시오.
    4KB는 4096바이트이고, 4096은 2^12이기 때문이다.
  16. CR3 레지스터는 무엇을 가리키는가?
    page directory base address.
  17. page directory entry와 page table entry의 역할을 설명하시오.
    PDE는 page table 위치를, PTE는 실제 page frame 위치를 가리킨다.
  18. page fault가 발생하는 대표적인 이유를 쓰시오.
    페이지가 present가 아니거나 접근 권한 위반이 있을 때.
  19. virtual memory와 physical memory의 차이를 설명하시오.
    virtual memory는 프로그램이 보는 주소 공간이고, physical memory는 실제 RAM 주소 공간이다.
  20. segmentation과 paging의 차이를 간단히 비교하시오.
    segmentation은 segment 단위의 base/limit/protection 변환이고, paging은 고정 크기 page 단위의 주소 매핑이다.

함정형 참거짓 True / False Traps

시험 직전에는 이 부분만 빠르게 돌려도 실수 방지 효과가 크다.

  1. NOT은 결과가 0이면 ZF를 1로 만든다.
    거짓. NOT은 플래그에 영향을 주지 않는다.
  2. TEST는 AND와 같은 논리 연산을 하지만 결과를 목적지에 저장하지 않는다.
    참.
  3. CMP는 내부적으로 뺄셈을 수행하지만 피연산자 값을 바꾸지 않는다.
    참.
  4. JE와 JZ는 같은 조건을 검사한다.
    참.
  5. signed 비교와 unsigned 비교는 같은 flag 조건을 사용하므로 점프 명령을 바꿀 필요가 없다.
    거짓. signed와 unsigned 점프는 반드시 구분해야 한다.
  6. LOOPNE는 ECX를 감소시키고, ECX != 0이며 ZF = 0이면 점프한다.
    참.
  7. LOOPNE는 점프 여부를 판단하면서 ZF 값을 새로 계산한다.
    거짓. 직전 명령의 ZF를 사용한다.
  8. SHR은 signed 음수의 부호를 보존한다.
    거짓. signed 부호 보존 오른쪽 shift는 SAR.
  9. SAR은 오른쪽 shift 때 최상위 비트를 유지하므로 signed 나눗셈에 적합하다.
    참.
  10. 32비트 MUL의 결과는 항상 EAX 하나에만 저장된다.
    거짓. 결과는 EDX:EAX.
  11. 32비트 DIV에서 피제수는 EDX:EAX이다.
    참.
  12. unsigned DIV 전에 EDX를 0으로 만들지 않으면 잘못된 결과나 divide error가 날 수 있다.
    참.
  13. signed IDIV 전에 CDQ는 불필요하다.
    거짓. 32비트 signed 피제수는 CDQ로 부호 확장해야 한다.
  14. IDIV의 나머지 부호는 divisor의 부호를 따른다.
    거짓. 피제수의 부호를 따른다.
  15. ADC는 CF까지 더한다.
    참.
  16. SBB는 CF까지 뺀다.
    참.
  17. STDCALL은 보통 callee가 stack을 정리한다.
    참.
  18. C calling convention은 보통 caller가 stack을 정리한다.
    참.
  19. [ebp+8]은 보통 첫 번째 매개변수이다.
    참.
  20. [ebp-4]는 보통 지역 변수 영역이다.
    참.
  21. 배열을 프로시저에 전달하면 배열의 모든 원소가 stack에 복사된다.
    거짓. 보통 배열 시작 주소가 전달된다.
  22. RET 8은 return address 8바이트를 제거한다는 뜻이다.
    거짓. return 후 매개변수 8바이트를 제거한다.
