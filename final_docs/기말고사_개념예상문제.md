# 시스템프로그래밍 기말고사 개념 예상문제

시험범위: 6장 조건 처리, 7장 정수 산술, 8장 고급 프로시저, 9장 메모리 관리

이 파일은 코드 작성보다 개념형, 참거짓, 단답형, 함정 설명 문제를 대비하기 위한 문제 세트이다. 먼저 문제만 풀고, 뒤의 정답을 확인한다.

## 2. 함정형 참거짓 문제

1. `NOT`은 결과가 0이면 `ZF`를 1로 만든다.

2. `TEST`는 `AND`와 같은 논리 연산을 하지만 결과를 목적지에 저장하지 않는다.

3. `CMP`는 내부적으로 뺄셈을 수행하지만 피연산자 값을 바꾸지 않는다.

4. `JE`와 `JZ`는 같은 조건을 검사한다.

5. signed 비교와 unsigned 비교는 같은 flag 조건을 사용하므로 점프 명령을 바꿀 필요가 없다.

6. `LOOPNE`는 `ECX`를 감소시키고, `ECX != 0`이며 `ZF = 0`이면 점프한다.

7. `LOOPNE`는 점프 여부를 판단하면서 `ZF` 값을 새로 계산한다.

8. `SHR`은 signed 음수의 부호를 보존한다.

9. `SAR`은 오른쪽 shift 때 최상위 비트를 유지하므로 signed 나눗셈에 적합하다.

10. 32비트 `MUL`의 결과는 항상 `EAX` 하나에만 저장된다.

11. 32비트 `DIV`에서 피제수는 `EDX:EAX`이다.

12. unsigned `DIV` 전에 `EDX`를 0으로 만들지 않으면 잘못된 결과나 divide error가 날 수 있다.

13. signed `IDIV` 전에 `CDQ`는 불필요하다.

14. `IDIV`의 나머지 부호는 divisor의 부호를 따른다.

15. `ADC`는 `CF`까지 더한다.

16. `SBB`는 `CF`까지 뺀다.

17. STDCALL은 보통 callee가 stack을 정리한다.

18. C calling convention은 보통 caller가 stack을 정리한다.

19. `[ebp+8]`은 보통 첫 번째 매개변수이다.

20. `[ebp-4]`는 보통 지역 변수 영역이다.

21. 배열을 프로시저에 전달하면 배열의 모든 원소가 stack에 복사된다.

22. `RET 8`은 return address 8바이트를 제거한다는 뜻이다.

23. `HeapAlloc`이 실패하면 반환값이 0인지 확인해야 한다.

24. `HeapFree`한 포인터는 다시 사용해도 안전하다.

25. `HEAP_ZERO_MEMORY`는 할당된 블록을 0으로 초기화한다.

26. page offset이 12비트이면 page size는 4KB이다.

27. `CR3`는 page directory의 base address를 가리킨다.

28. page fault는 오직 물리 메모리가 완전히 가득 찼을 때만 발생한다.

29. segmentation은 segment descriptor를 통해 base, limit, access right 등을 사용한다.

30. virtual address와 physical address는 항상 같은 값이다.

## 3. 정답

### 6장 정답

1. `CF=0`, `OF=0`으로 클리어된다.
2. 플래그에 영향을 주지 않는다.
3. 둘 다 bitwise AND 연산을 기준으로 flag를 설정한다. `AND`는 결과를 저장하고, `TEST`는 결과를 버린다.
4. 둘 다 뺄셈 기준으로 flag를 설정한다. `SUB`는 결과를 저장하고, `CMP`는 피연산자를 바꾸지 않는다.
5. `JA`는 unsigned greater, `JG`는 signed greater.
6. signed 값의 대소 관계는 `SF`, `OF`, `ZF` 조합으로 판단해야 하므로 unsigned 점프를 쓰면 음수에서 틀린다.
7. unsigned 값의 대소 관계는 `CF`, `ZF` 중심으로 판단해야 하므로 signed 점프를 쓰면 최상위 bit가 1인 값에서 틀린다.
8. 같은 조건이다. 둘 다 `ZF=1`.
9. 같은 조건이다. 둘 다 `ZF=0`.
10. `CF=0 AND ZF=0`.
11. `CF=1 OR ZF=1`.
12. `ZF=0 AND SF=OF`.
13. `SF != OF`.
14. 하나라도 거짓이면 false label로 빠지는 방식이 흔하다.
15. 하나라도 참이면 true label로 바로 점프하는 방식이 흔하다.
16. `ECX`.
17. `LOOPE`: `ECX != 0` and `ZF=1`, `LOOPNE`: `ECX != 0` and `ZF=0`.
18. 변경하지 않는다. 직전 명령이 만든 `ZF`를 사용한다.
19. MASM이 생성하는 signed/unsigned 비교를 정확히 의식해야 한다.
20. bit 5를 끈다. 보통 `AND 11011111b`.

### 7장 정답

21. 왼쪽으로 n비트 shift하면 보통 `2^n` 곱셈과 같다.
22. 빈자리를 0으로 채워 unsigned 값을 논리적으로 나누기 때문이다.
23. signed 음수의 부호 bit를 유지해야 하기 때문이다.
24. `ROL`은 CF를 회전 대상에 포함하지 않고, `RCL`은 CF까지 포함해 회전한다.
25. 8비트: `AX`, 16비트: `DX:AX`, 32비트: `EDX:EAX`.
26. `MUL`은 unsigned, `IMUL`은 signed 곱셈이다.
27. 8비트: 피제수 `AX`, 몫 `AL`, 나머지 `AH`; 16비트: 피제수 `DX:AX`, 몫 `AX`, 나머지 `DX`; 32비트: 피제수 `EDX:EAX`, 몫 `EAX`, 나머지 `EDX`.
28. `DIV`은 상위:하위 전체를 피제수로 보기 때문에 상위 절반이 쓰레기 값이면 잘못된 피제수가 된다.
29. signed 피제수를 올바르게 상위 절반까지 부호 확장하기 위해서다.
30. `CBW`: `AL -> AX`, `CWD`: `AX -> DX:AX`, `CDQ`: `EAX -> EDX:EAX`.
31. 피제수의 부호를 따른다.
32. divisor가 0인 경우, 또는 몫이 destination 크기에 들어가지 않는 경우.
33. `CF`까지 더한다.
34. `CF`까지 뺀다.
35. 하위 계산에서 발생한 carry/borrow를 상위 계산에 전달해야 하기 때문이다.
36. 결과의 상위 절반이 0이 아니면 `CF=1`, `OF=1`.
37. 항상 좋은 것은 아니다. 표현이 복잡해질 수 있고 overflow, signed 의미, 가독성을 고려해야 한다.
38. 특정 bit field만 분리하기 위해 mask로 불필요한 bit를 지우고 shift로 위치를 맞춘다.
39. `EDX`는 상위 32비트, `EAX`는 하위 32비트.
40. `EDX:EAX` 피제수의 부호 확장이 틀려 `IDIV` 결과가 틀리거나 divide error가 날 수 있다.

77. PDE는 page table 위치를, PTE는 실제 page frame 위치를 가리킨다.
78. 페이지가 present가 아니거나 접근 권한 위반이 있을 때.
79. virtual memory는 프로그램이 보는 주소 공간이고, physical memory는 실제 RAM 주소 공간이다.
80. segmentation은 segment 단위의 base/limit/protection 변환이고, paging은 고정 크기 page 단위의 주소 매핑이다.
