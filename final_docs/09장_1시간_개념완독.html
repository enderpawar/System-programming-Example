1. Dynamic Memory Allocation

개념

동적 메모리 할당

객체나 배열이 실행 중에 만들어질 때 필요한 저장 공간을 예약하는 기법입니다. 보통 heap allocation이라고 부릅니다.

관리자

Heap manager

프로그램 시작 시 운영체제에서 큰 메모리 블록을 얻고, free list로 빈 블록을 관리합니다.

흐름

할당과 해제

할당은 충분히 큰 빈 블록을 찾아 예약 표시하고 포인터를 반환합니다. 해제는 블록을 다시 free list로 돌려놓습니다.

Windows Heap API 암기표

API역할시험용 암기 포인트
GetProcessHeap현재 프로그램의 기존 힙 핸들을 가져옵니다.반환값은 EAX의 heap handle.
HeapCreate현재 프로그램을 위한 private heap을 새로 만듭니다.초기/최대 힙 크기는 page boundary로 올림. 필요 시 커질 수 있음.
HeapAlloc기존 힙에서 메모리 블록을 할당합니다.반환값은 EAX의 새 저장 공간 포인터. HEAP_ZERO_MEMORY를 쓰면 0으로 초기화.
HeapFree이전에 할당한 메모리 블록을 해제합니다.기본 dwFlags는 NULL.
HeapDestroyHeapCreate로 만든 private heap을 제거합니다.private heap 전용 마무리 함수.
GetLastErrorAPI 오류의 세부 정보를 얻습니다.HeapCreate, HeapDestroy, GetProcessHeap 오류 확인에 사용.

2. x86 Memory Management 기본 용어

멀티태스킹과 세그먼트

  • Multitasking: 여러 프로그램이 동시에 실행되는 것처럼 CPU 시간을 나누어 쓰는 방식.
  • Segment: 프로그램이 쓰는 가변 크기 메모리 영역. 코드나 데이터를 담습니다.
  • Segmentation: 세그먼트끼리 분리해 프로그램들이 서로 간섭하지 않게 하는 보호 장치.

주소 관련 용어

  • Segment descriptor: 세그먼트의 base address, 접근 권한, 크기 제한, 타입, 용도를 설명합니다.
  • Segment selector: CS, DS, SS, ES, FS, GS 같은 세그먼트 레지스터에 저장되는 16비트 값.
  • Logical address: segment selector와 32비트 offset의 조합.

3. Logical Address -> Linear Address

멀티태스킹 운영체제에서는 각 프로그램이 자기 데이터 영역을 가진 것처럼 보입니다. 예를 들어 세 프로그램이 모두 offset 200h에 변수를 가져도 실제 주소는 충돌하면 안 됩니다.

32-bit linear address = segment base address + 32-bit offset

segment selector는 descriptor table의 segment descriptor를 가리키고, descriptor 안에 segment base address가 있습니다.

4. Paging과 Page Translation

왜 쓰나

메모리보다 큰 실행 환경

프로그램 전체를 한 번에 메모리에 올리지 않고 필요한 page만 메모리에 두어 여러 프로그램을 실행할 수 있게 합니다.

단위

Page

프로그램 메모리를 작은 단위로 나눈 것입니다. 보통 4KB page를 사용합니다.

예외

Page fault

요청한 page가 메모리에 없으면 page fault가 발생하고, 운영체제가 디스크에서 필요한 page를 가져온 뒤 실행을 재개합니다.

32비트 선형 주소의 분해

[ 10-bit directory ][ 10-bit table ][ 12-bit offset ]
1선형 주소가 선형 주소 공간의 한 위치를 가리킵니다.
2directory 필드가 page directory entry의 인덱스가 됩니다.
3page directory entry가 page table의 base address를 담습니다.
4table 필드가 page table entry의 인덱스가 됩니다.
5page base address + offset = 실제 physical address.

CR3 레지스터는 page directory의 시작 주소를 담습니다.

5. Descriptor Table과 Segment Descriptor

GDT와 LDT

  • GDT: 운영체제가 부팅 중 protected mode로 전환할 때 생성하는 전역 descriptor table.
  • LDT: 멀티태스킹 OS에서 각 task나 program에 보통 배정되는 local descriptor table.
  • LDTR: 프로그램의 LDT 주소를 담는 레지스터.

Segment Descriptor 필드

  • Base address: 4GB 선형 주소 공간에서 세그먼트 시작 위치.
  • Privilege level: 0~3. 0이 가장 높은 권한이며 보통 OS kernel code.
  • Segment type: 데이터/스택/코드, 읽기/쓰기/실행, 성장 방향 등을 표현.
  • Present flag: 세그먼트가 물리 메모리에 있는지 표시.
  • Granularity flag: segment limit을 byte 단위로 볼지 4096-byte 단위로 볼지 결정.
  • Segment limit: 세그먼트 크기 제한. granularity에 따라 1B~1MB 또는 4KB~4GB 범위.

마지막 3분 암기 체크리스트

확인 문제

1. HeapCreate와 GetProcessHeap의 차이는?

GetProcessHeap은 프로그램의 기존 힙 핸들을 가져오고, HeapCreate는 새 private heap을 만든다.

2. HEAP_ZERO_MEMORY 옵션의 효과는?

HeapAlloc으로 받은 메모리 블록을 모두 0으로 초기화한다.

3. Segment descriptor에는 어떤 정보가 들어가는가?

base address, access rights/privilege, size limit, type, usage, present flag, granularity 등 세그먼트를 설명하는 정보가 들어간다.

4. 논리 주소에서 선형 주소를 계산하는 공식은?

32-bit linear address = segment base address + 32-bit offset.

5. page fault는 언제 발생하는가?

요청한 page가 현재 물리 메모리에 없을 때 발생한다. 운영체제가 디스크에서 page를 가져온 뒤 프로그램을 재개한다.

6. page directory, page table, page는 각각 무엇인가?

page directory는 page-directory entry 배열, page table은 page-table entry 배열, page는 4KB 또는 4MB 주소 공간 단위이다.

7. 32비트 linear address의 세 필드는?

10-bit directory, 10-bit table, 12-bit offset.
