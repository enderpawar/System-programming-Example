## 3. 조건 처리 핵심 요약

### Boolean 명령어와 flag

| 명령어 | 동작 | flag |
|---|---|---|
| `AND` | 비트 끄기, 교집합, 마스킹 | `CF=0`, `OF=0`, `SF/ZF/PF`는 결과 따라 |
| `OR` | 비트 켜기, 합집합 | `CF=0`, `OF=0`, `SF/ZF/PF`는 결과 따라 |
| `XOR` | 비트 토글, 간단 암호화 | `CF=0`, `OF=0`, `SF/ZF/PF`는 결과 따라 |
| `NOT` | 모든 비트 반전 | flag 변경 없음 |
| `TEST` | `AND`처럼 flag만 계산 | 목적지는 변하지 않음, `CF=0`, `OF=0` |
| `CMP` | `dest - src`처럼 flag 계산 | 피연산자는 변하지 않음 |

필수 예시:

```asm
and al, 11011111b    ; 소문자 -> 대문자, bit 5 clear
or  al, 00100000b    ; 대문자 -> 소문자, bit 5 set
xor al, 00100000b    ; 대소문자 토글
test al, 00100000b   ; bit 5가 켜졌는지만 검사
```

### 조건부 점프 표

| 의미 | unsigned | 조건 | signed | 조건 |
|---|---|---|---|---|
| `>` | `JA` | `CF=0 AND ZF=0` | `JG` | `ZF=0 AND SF=OF` |
| `>=` | `JAE` | `CF=0` | `JGE` | `SF=OF` |
| `<` | `JB` | `CF=1` | `JL` | `SF!=OF` |
| `<=` | `JBE` | `CF=1 OR ZF=1` | `JLE` | `ZF=1 OR SF!=OF` |
| `==` | `JE/JZ` | `ZF=1` | `JE/JZ` | `ZF=1` |
| `!=` | `JNE/JNZ` | `ZF=0` | `JNE/JNZ` | `ZF=0` |

기억법:

- A/B = Above/Below = unsigned
- G/L = Greater/Less = signed
- `cmp left, right` 후 점프는 `left ? right` 기준으로 읽는다.
- `cmp eax, ebx` 다음 `ja L1`은 `eax > ebx`일 때 점프다.

### IF/WHILE 변환 정석

IF-ELSE는 보통 조건을 반대로 뒤집어 false label로 보낸다.

```asm
; if (VAR1 < VAR2) VAR5 = 1; else VAR5 = 0;  signed
mov eax, VAR1
cmp eax, VAR2
jge L_FALSE
mov VAR5, 1
jmp L_END
L_FALSE:
mov VAR5, 0
L_END:
```

복합 AND는 하나라도 false면 탈출한다.

```asm
; if (a <= b && c != d) x = 1; else x = 0; signed
mov eax, a
cmp eax, b
jg  L_FALSE       ; a <= b의 반대
mov eax, c
cmp eax, d
je  L_FALSE       ; c != d의 반대
mov x, 1
jmp L_END
L_FALSE:
mov x, 0
L_END:
```

복합 OR는 하나라도 true면 true label로 보낸다.

```asm
; if (VAR1 < VAR2 || VAR3 >= VAR4) VAR5 = 1; signed
mov eax, VAR1
cmp eax, VAR2
jl  L_TRUE
mov eax, VAR3
cmp eax, VAR4
jge L_TRUE
jmp L_END
L_TRUE:
mov VAR5, 1
L_END:
```

WHILE은 종료 조건으로 점프한다.

```asm
; while (eax < 10) { inc eax; add sum,eax; } unsigned
mov eax, 0
L1:
cmp eax, 10
jae L2
inc eax
add sum, eax
jmp L1
L2:
```

### 조건부 루프

| 명령어 | 점프 조건 |
|---|---|
| `LOOPE`, `LOOPZ` | `ECX` 감소 후 `ECX != 0` 그리고 `ZF=1` |
| `LOOPNE`, `LOOPNZ` | `ECX` 감소 후 `ECX != 0` 그리고 `ZF=0` |

주의:

- `LOOPxx` 자체는 flag를 바꾸지 않는다.
- 루프 안의 `ADD`, `INC`, `SUB` 등이 `ZF`를 덮으면 `PUSHFD/POPFD`로 보존해야 할 수 있다.

## 4. 정수 산술 핵심 요약

### Shift/Rotate

| 명령어 | 핵심 |
|---|---|
| `SHL/SAL` | 왼쪽 shift, LSB에 0, MSB가 `CF`, unsigned 곱하기 `2^n` |
| `SHR` | 오른쪽 논리 shift, MSB에 0, unsigned 나누기 `2^n` |
| `SAR` | 오른쪽 산술 shift, sign bit 복제, signed 나누기 `2^n` |
| `ROL/ROR` | 비트가 양 끝에서 회전, `CF`에도 나간 bit 반영 |
| `RCL/RCR` | `CF`까지 포함해서 회전 |

상수 곱셈 최적화:

```asm
; eax = var * 72 = var * (64 + 8)
mov eax, var
mov ebx, eax
shl eax, 6
shl ebx, 3
add eax, ebx
```

비트 필드 추출:

```asm
; datestamp: bit 5~8 = month
mov ax, datestamp
shr ax, 5
and ax, 0000000000001111b
```

### MUL/IMUL

| 피연산자 크기 | 암시 피승수 | 결과 |
|---|---|---|
| 8비트 | `AL` | `AX` |
| 16비트 | `AX` | `DX:AX` |
| 32비트 | `EAX` | `EDX:EAX` |

필수:

- `MUL`은 unsigned, 피연산자 1개, immediate 불가.
- `MUL` 결과의 상위 절반이 0이 아니면 `CF=1`, `OF=1`.
- 1-operand `IMUL`은 signed이고 결과 저장 위치는 `MUL`과 같다.
- 2/3-operand `IMUL`은 결과가 목적지 크기로 잘릴 수 있고, significant bits가 손실되면 `CF=OF=1`.

### DIV/IDIV

| 제수 크기 | 피제수 | 몫 | 나머지 |
|---|---|---|---|
| 8비트 | `AX` | `AL` | `AH` |
| 16비트 | `DX:AX` | `AX` | `DX` |
| 32비트 | `EDX:EAX` | `EAX` | `EDX` |

필수:

- `DIV`: unsigned. 나누기 전 상위 절반을 0으로 만든다.
- `IDIV`: signed. 나누기 전 피제수를 부호 확장한다.
- `CBW`: `AL -> AX`
- `CWD`: `AX -> DX:AX`
- `CDQ`: `EAX -> EDX:EAX`
- `IDIV`의 나머지 부호는 피제수의 부호와 같다.
- 0으로 나누거나 몫이 목적지에 안 들어가면 divide error가 난다.

예시:

```asm
; unsigned 32-bit: eax / ebx
mov eax, dividend
mov edx, 0
div ebx              ; quotient=eax, remainder=edx

; signed 32-bit: eax / ebx
mov eax, dividend
cdq
idiv ebx             ; quotient=eax, remainder=edx
```

산술식 변환:

```asm
; VAR4 = (-VAR1 * 5) / (VAR2 * VAR3), signed DWORD
mov eax, VAR2
imul eax, VAR3       ; eax = VAR2*VAR3
mov ebx, eax         ; divisor

mov eax, VAR1
neg eax
imul eax, 5
cdq
idiv ebx
mov VAR4, eax
```

나머지 식:

```asm
; VAR4 = (4 * VAR1) % (VAR2 - VAR3), signed DWORD
mov eax, VAR1
shl eax, 2
mov ebx, VAR2
sub ebx, VAR3
cdq
idiv ebx
mov VAR4, edx
```

### ADC/SBB

```asm
; FFFFFFFFh + FFFFFFFFh = 00000001FFFFFFFEh
mov edx, 0
mov eax, 0FFFFFFFFh
add eax, 0FFFFFFFFh
adc edx, 0

; 0000000100000000h - 1 = 00000000FFFFFFFFh
mov edx, 1
mov eax, 0
sub eax, 1
sbb edx, 0
```

## 5. Stack frame과 calling convention

### 기본 stack frame

```asm
push ebp
mov  ebp, esp
sub  esp, local_size
; 필요하면 push로 register 보존
...
mov  esp, ebp
pop  ebp
ret
```

인자 위치:

- `[ebp+4]`: return address
- `[ebp+8]`: 첫 번째 인자
- `[ebp+12]`: 두 번째 인자
- `[ebp-4]`: 첫 번째 local DWORD

### C calling convention

- 인자는 오른쪽부터 push.
- caller가 stack 정리: `add esp, 인자크기`.
- 프로시저는 보통 `ret`.

```asm
push OFFSET y
push OFFSET x
call swap
add esp, 8
```

### STDCALL

- 인자는 오른쪽부터 push.
- callee가 stack 정리: `ret 8`.
- caller는 `add esp,8` 하지 않는다.

```asm
push OFFSET y
push OFFSET x
call swap
```

### swap 정답 템플릿

```asm
swap PROC
    push ebp
    mov  ebp, esp
    sub  esp, 4
    push eax
    push ebx
    push edx

    mov  eax, [ebp+8]     ; a
    mov  ebx, [ebp+12]    ; b
    mov  edx, [eax]
    mov  [ebp-4], edx     ; temp = *a
    mov  edx, [ebx]
    mov  [eax], edx       ; *a = *b
    mov  edx, [ebp-4]
    mov  [ebx], edx       ; *b = temp

    pop  edx
    pop  ebx
    pop  eax
    mov  esp, ebp
    pop  ebp
    ret  8                ; STDCALL. C convention이면 ret
swap ENDP
```

## 6. 메모리 관리 방어 요약

기출 참거짓 핵심:

- 동적 메모리 할당은 운영체제에 heap 메모리 블록을 요청하고 주소를 받는다.
- 지역변수는 stack frame에 있다.
- 동적 할당 메모리는 프로시저가 return된다고 자동 해제되지 않는다.
- logical address는 segment selector + offset이다.
- linear address는 segment base + offset으로 계산된다.
- paging을 사용하면 linear address가 page translation을 거쳐 physical address로 변환된다.
- page fault는 요청 page가 메모리에 없거나 접근 권한 문제가 있을 때 발생한다.
- cache miss와 page fault는 다르다. cache에 없다고 page fault가 아니다.
- 같은 page 내부에서 연속된 linear address는 같은 page frame 안에서는 physical도 연속이지만, 서로 다른 page끼리는 연속 보장 안 된다.

## 7. REAL4 방어 요약

REAL4는 IEEE 754 single precision이다.

구성:

- sign 1비트
- exponent 8비트, bias 127
- fraction 23비트

변환 절차:

1. 10진수를 2진수로 바꾼다.
2. `1.xxxxx * 2^e` 꼴로 정규화한다.
3. exponent field = `e + 127`.
4. sign/exponent/fraction을 이어 붙여 32비트 hex로 만든다.
5. 메모리 저장은 little endian이므로 낮은 주소부터 byte 순서를 뒤집어 쓴다.

예시:

```text
0.15625 = 0.00101b = 1.01b * 2^-3
sign = 0
exponent = -3 + 127 = 124 = 7Ch
fraction = 010000...
bit pattern = 3E200000h
memory = 00 00 20 3E
```

2024년 유형처럼 `3FC00000h`가 나오면:

```text
sign=0, exponent=127, fraction=.5
값 = 1.5 * 2^0 = 1.5
```

## 8. 실수 방지 체크리스트

시험장에서 답 쓰기 전 확인:

1. `cmp mem, mem`을 쓰지 않았는가? 한쪽은 레지스터로 옮겨라.
2. signed 문제에 `JA/JB/JAE/JBE`를 쓰지 않았는가?
3. unsigned 문제에 `JG/JL/JGE/JLE`를 쓰지 않았는가?
4. `IDIV` 전에 `CDQ/CWD/CBW`를 했는가?
5. `DIV` 전에 `EDX/DX/AH`를 0으로 만들었는가?
6. 나머지를 요구하면 `EAX`가 아니라 `EDX`, `AX`가 아니라 `DX`, `AL`이 아니라 `AH`를 저장했는가?
7. STDCALL 호출 뒤에 `add esp,8`을 쓰지 않았는가?
8. C calling convention 호출 뒤에는 `add esp,8`을 썼는가?
9. `MUL`에 immediate를 쓰지 않았는가?
10. 8비트 `MUL/DIV`는 `AL/AX/AH`를 쓰는 것을 잊지 않았는가?
11. `LOOPNE/LOOPE` 직전의 `ZF`가 중간 명령어로 덮이지 않았는가?
12. REAL4 메모리 문제에서 little endian으로 byte 순서를 뒤집었는가?

## 9. 마지막 암기표

```text
AND/OR/XOR/TEST: CF=0, OF=0
NOT: flag 변경 없음
CMP: dest-src 기준, operand 변경 없음

unsigned: JA/JAE/JB/JBE
signed:   JG/JGE/JL/JLE
JE=JZ, JNE=JNZ

MUL r/m8  : AL*op -> AX
MUL r/m16 : AX*op -> DX:AX
MUL r/m32 : EAX*op -> EDX:EAX

DIV r/m8  : AX/op -> AL, AH
DIV r/m16 : DX:AX/op -> AX, DX
DIV r/m32 : EDX:EAX/op -> EAX, EDX

DIV 전: 상위 절반 0
IDIV 전: CBW/CWD/CDQ

ADC = add + CF
SBB = sub - CF

C convention: caller cleanup, ret + add esp,n
STDCALL: callee cleanup, ret n
```

## 10. 추천 풀이 순서

1. 참거짓/개념 문제를 먼저 풀어 점수를 확보한다.
2. 조건부 점프 표 문제는 실수 없이 바로 쓴다.
3. `swap`은 템플릿을 그대로 재현한다.
4. C/C++ 변환 문제는 signed/unsigned를 먼저 표시하고 시작한다.
5. 산술식 문제는 divisor를 `EBX`, dividend/result를 `EAX`, remainder를 `EDX`로 고정한다.
6. 실행 결과 추적 문제는 각 명령어 뒤 register와 flag를 한 줄씩 적는다.
